# タスク確認

Todoistから最新のタスクを取得し、一覧表示する。

## 手順

1. `node ~/.claude/scripts/todoist-tasks.mjs --format json` を Bash で実行してタスク一覧を取得する
   - 必ず毎回このスクリプトを再実行すること。
   - **前回の取得結果・会話内のキャッシュを使い回してはいけない（タスクは随時追加・完了されるため、古い一覧をそのまま再表示するのは禁止）**
   - スクリプトが Todoist MCP (`mcp-remote`) を呼び、優先度・投稿日時の機械的な抽出とソートまで済ませた JSON を返す
2. 以下のフォーマットで一覧表示する

### スクリプトの出力フィールド

JSON 配列で、各要素は以下のフィールドを持つ（優先度→投稿日時の順でソート済み）:

| フィールド | 内容 |
|------------|------|
| `id` | TodoistタスクID（完了処理に使う） |
| `content` | タスク本文（生・全文） |
| `description` | 説明文（生・全文、`From` 名と `[Slack](...)` を含む） |
| `priority` | `p1`〜`p4` |
| `from` | 依頼元（`○○さん` または `自分`） |
| `posted_at_jst` | 投稿日時 `MM/DD HH:MM`（Slackリンクなしなら空） |
| `slack_url` | Slack URL（クエリパラメータ込みの完全形） |
| `thread_ts` | Slackスレッドの識別子（同スレッド判定・ツリー表示に使う／無ければ空） |
| `is_thread_child` | 同一スレッドの2件目以降なら `true`（ツリーの子として描画する） |
| `due` | 期限 `YYYY-MM-DD HH:MM`（なければ空） |
| `recurring` | 繰り返し設定（文字列または false） |
| `project_id` | プロジェクトID |
| `labels` | ラベル配列 |

## 表示フォーマット

- 1つのテーブルで表示する
- 列: `#`（通し番号）、`内容`、`優先度`、`依頼元`、`投稿日時`、`URL`
- 通し番号は1から連番で振る（日をまたいだら1から再採番）
- `内容` は `content` を **Claude側で1行に要約する**（メンションだけの行はスキップして本文を拾う／長文はそのまま貼らない）
- `優先度` / `依頼元` / `投稿日時` はスクリプトの値をそのまま使う
- `URL` は `slack_url` をそのまま `[Slack](...)` 形式に包む（クエリパラメータも省略しない）
- 期限がある場合は内容の末尾に `（期限: YYYY-MM-DD HH:MM）` を付与する
- 同一スレッドのタスクはツリー表示する。スクリプトが同 `thread_ts` のタスクを連続させ、2件目以降に `is_thread_child: true` を付けて返すので、`is_thread_child` が `true` の行は `内容` の先頭に `┗ ` を付ける（順番はスクリプトの並びをそのまま使う）

## 表示例

| # | 内容 | 優先度 | 依頼元 | 投稿日時 | URL |
|---|------|--------|--------|----------|-----|
| 1 | 本番DBマイグレーション実行 | p1 | 自分 | 04/10 09:30 | |
| 2 | PR#123 レビュー | p3 | 田中さん | 04/12 14:20 | [Slack](https://peraichi.slack.com/...) |
| 3 | リマインドメール仕様の問い合わせ | p4 | 武田さん | 04/13 11:05 | [Slack](https://peraichi.slack.com/...) |
| 4 | ┗ 仕様確認の進捗どうですか？ | p4 | 鈴木さん | 04/14 09:00 | [Slack](https://peraichi.slack.com/...) |

## タスク完了時のスレッド確認

ユーザーがタスクを完了する際、以下の手順を実行する:

1. 完了対象タスクのSlackリンクから `thread_ts` を抽出する（`cid` はチャンネルIDなのでスレッド判定には使わない）
2. 残りの未完了タスクの中に、同じ `thread_ts` を持つタスクがあるか確認する
3. 該当タスクがあれば、「同じスレッドのタスクも完了しますか？」と該当タスクの一覧（#番号と内容）を提示して確認する
4. ユーザーが承認したら、まとめて完了する

## タスク一覧表示時の自動完了提案

タスク一覧を表示した際、以下に該当するタスクがあれば「アクション不要のタスクがあります。完了しますか？」と提案する:

- スケジュール調整・参加依頼のみのタスク
- 単なる連絡・共有で、ユーザーのアクションが不要なもの

以下は提案対象外とする（ユーザーの確認・対応が必要なため）:
- 情報共有だが内容の確認や判断が求められるもの（メリデメ比較、方針案など）
- 質問・相談が含まれるもの

提案時は該当タスクの#番号と内容を一覧で提示し、ユーザーの承認を得てから完了する。
